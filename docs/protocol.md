# GalaxySidecar wire protocol

Update the host and viewer together for H.264. The viewer sends a 64-byte connection token or 64 zero bytes for view-only use. The host replies with `GSC2` and a capability byte. Bit 0 means input is enabled, bit 2 means H.264, and the value 2 means pairing was rejected. H.264 adds width and height as two big-endian UInt16 values. Each video packet has a 4-byte unsigned big-endian length followed by an Annex B H.264 access unit or JPEG bytes (8 MiB max). The viewer sends a 13-byte acknowledgment after submitting a frame. Pointer messages use the same size, with a type byte and three big-endian Float32 values for normalized x, y, and pressure. Their type is 1 for down, 2 for drag, 3 for up, or 4 for hover, with the high bit set for pen.

The host preserves aspect ratio and caps H.264 at a 1920-pixel long edge. It keeps one pending capture before encoding and allows up to two H.264 frames in flight. JPEG keeps one frame in flight. H.264 adjusts its target bitrate between 0.9 and 7 Mbps using receiver acknowledgment times, while resolution stays fixed for the session. Every 60 delivered frames, the host logs FPS, bitrate, and p50/p95 time from capture callback through Android frame submission and return acknowledgment. The timing omits Android scanout. JPEG selected with `--jpeg` caps the longest edge at 1280 pixels.

For input-enabled sessions, capability bit 3 enables trackpad, clipboard, shortcuts, and heartbeats. Client messages 8 and 9 push and request clipboard text. A push includes its byte length as a UInt32 at offset 1 followed by the UTF-8 bytes after the 13-byte message. Server video lengths of zero signal a clipboard response or heartbeat. The next signed Int32 is the clipboard byte count (maximum 64 KiB) or -1 for a heartbeat. Trackpad messages use types 10–15, and shortcuts use type 16.
